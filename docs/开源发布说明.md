# 开源与发布

## 目录就是公开源码

当前 `markdown_a` 直接作为仓库根目录使用，保留应用源码、测试、内置图文与图源、Gradle Wrapper、依赖摘要、CI、项目文档、许可证，以及 `release/纸墨Markdown.apk` 和校验文件。

目录不保留旧 Git 历史、本机 SDK 配置、签名私钥、下载网页、源码压缩包、局域网服务脚本或构建缓存。旧历史与 SDK 配置已另存于工程外的本地备份。不要把该备份一起上传。

可在此目录新建 Git 仓库后正常提交，也可以向新仓库上传目录内容；请保留 `.github`、`.gitignore`、`.gitattributes` 等项目文件。`.gitignore` 允许提交唯一的预编译 APK，其他 APK 和生成物继续忽略。

## 给不编译的使用者

`release/纸墨Markdown.apk` 已签名，可直接安装。它是关闭应用与原生调试、启用 R8 和资源压缩的 Release 构建；SHA-256 见同目录 `SHA256SUMS.txt`。网页和临时服务器不是安装所需条件，可以通过仓库下载 APK，或者自行将 APK 作为 Release 附件发布。

本次沿用旧测试包签名证书，便于覆盖升级，没有把私钥放进源码。证书名称不会开启应用调试。维护者另用专用密钥后，应说明与旧证书安装包的更新关系。

## 给自行编译的开发者

使用 JDK 17、SDK platform 36 和 build-tools 35.0.0：

```sh
bash gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleRelease
```

Windows 可用 `gradlew.bat` 或 `powershell -File tools/build.ps1`。APK 签名环境变量见 README。未提供密钥时，Gradle 输出 unsigned Release 用于构建检查，不能安装；不会自动拥有仓库预编译 APK 的签名。

配图已随源码提供，构建不需要 draw.io。修改图源时可运行 `python tools/render-sample-diagrams.py --render`。更新依赖时检查来源和新的校验摘要，不要关闭验证。

公开 CI 不包含维护者密钥；签名私钥和密码始终在工程外保管，不能提交。发布前按 `验收清单.md` 验证真实设备、输入法、文件提供方和 Release 行为。许可证与第三方声明见根目录 LICENSE、NOTICE 和 LICENSES。
